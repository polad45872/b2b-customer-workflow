# 发现优先的系统搜索

保留SYSTEM_SEARCH主路径：以实际企业、产品服务、业务场景、项目和来源名单构造查询，优先复用有新增入池候选的路径，再探索新路径，并在增量下降时补覆盖缺口。

计划控制器保留LIST_EXTRACTION、PRODUCT_PROCESS、HIRING_PROCUREMENT、PROJECT_TRACE四类发现方法。PRODUCT_PROCESS名称用于兼容原控制协议，内容现在可以是产品服务与业务流程，不限定设备工序。

受控查询从绑定词库的五类用途模板生成；自定义查询必须说明变更依据、发现方法和来源入口，并通过已有计划校验。Worker不得修改分配的query_id或query_text。

沿用历史产出优先分配、缺口分配和探索分配。无历史产出时走冷启动，不能编造高产来源。候选新增按全局去重后的入池企业计数，不按FINAL数量计算。

停止前按绑定策略检查连续合格且独立的零新增SYSTEM_SEARCH轮次：standard/light至少3轮、每轮8条；strict至少4轮、每轮12条。重复查询、访问失败和定向核验不能充数。一个轮次可拆多个核验批次，批次关闭不等于轮次结束。仍有覆盖缺口、未处置候选或扩展缺口时继续推进。

脚本生成计划及审计记录。执行Agent实际浏览、判断来源与企业线索；计划存在不证明查询已执行。
